## Core Concepts

### Three-Tier Architecture

1. **Collector Tier** (server-side, scheduled)
   - Runs every 5 minutes via GitHub Actions
   - Calls GitHub REST API for workflow run data
   - Normalizes and writes `data/status.json`
   - Commits only when changed

2. **Deployment Tier** (triggered by pushes)
   - Deploys entire repo to GitHub Pages
   - Runs on every push to `main`
   - Uses OIDC token (no secrets)

3. **Presentation Tier** (client-side, static)
   - Loads `index.html` → ES modules
   - Fetches `data/status.json` with cache-busting
   - Renders dashboard, auto-refreshes every 60s
   - Theme toggle, manual refresh, pipeline detail dialog

### Data Flow

```
GitHub Actions (backend/frontend/system-status) 
    │
    ▼ gh api (collector)
Collector Script → data/status.json 
    │
    ▼ git commit + push
GitHub Pages Deploy 
    │
    ▼ HTTPS
Browser → fetch(status.json) → Render Dashboard
```

### Key Invariants

1. **Collector never fabricates data** — missing = "Unknown", errors surfaced
2. **Frontend never triggers collector** — Refresh = fetch only
3. **Theme persists in localStorage** — applied before paint via inline script
4. **Status.json committed only on change** — `cmp -s` prevents noise
5. **All colors via CSS variables** — no hardcoded colors anywhere

## Gotchas and Tribal Knowledge

### Theme System
- Inline script in `<head>` sets `data-theme` BEFORE CSS loads — prevents flash
- Do NOT move theme script to `app.js` — causes flash
- Logo swap via CSS: `[data-theme="light"] .logo-dark { display: none }`

### Collector
- Uses `gh api` with query params in URL: `?branch=main&per_page=5`
- `gh api -f` is for path params, NOT query params
- Discovers workflows via `/actions/workflows`, then fetches runs per workflow
- `cmp -s` for byte comparison — only commits on actual change
- Push uses `GITHUB_TOKEN` (built-in), NOT the PAT

### Frontend
- `statusApi.fetchStatus()` adds `?t=Date.now()` for cache-busting
- `setInterval` in `app.js` — errors caught, timer continues
- Manual refresh: `Promise.race([renderDashboard(), timeout])` — 10s timeout
- `workflow.effectiveStatus` from the collector is the SINGLE source of truth for display status
- Footer release label comes from `package.json` via `fetchReleaseVersion()`

### Responsive
- Three-area header: Brand (left) | Actions (center, `flex-shrink: 1`) | Last Updated (right, `margin-left: auto`)
- Mobile (≤429px): Last Updated wraps to row 2 with `border-top`
- Release test widths: 320, 375, 430, 768, 1024, 1440px

### Deployment
- Collector commit → triggers `deploy-pages.yml` → live in 2-5 min
- Pages source MUST be "GitHub Actions" in repo settings
- `CNAME` empty — do NOT add domain until DNS ready
